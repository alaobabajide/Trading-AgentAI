01

What the System Actually Is

The single most important finding: seven of the twenty-seven agents claim domain expertise they do not have. The MacroEconomist has never seen a yield curve. The Options Flow Analyst has never seen a put/call ratio. The FundamentalAnalyst frequently runs on an empty data dictionary. What is advertised as a multi-discipline debate is, in practice, a 27-voice technical analysis system wearing specialist costumes.

The system's signal quality is not 27-dimensional — it is closer to 3-dimensional: a strong technical signal layer, a weak and inconsistent sentiment layer, and an unreliable fundamental layer. The "macro," "options flow," "quant," and "sector rotation" voices are all re-reading the same OHLCV data the technical analyst already processed.

02

Three-Year Backtest Assessment

A reproducible backtest is not currently possible. The live system relies on LLM calls whose outputs are non-deterministic — running the same market data through the same agents twice produces different votes. There is no replay harness, no simulated broker, no transaction cost model, and no signal persistence layer for historical data. The only backtestable path is paper-mode (rule-based risk manager, no LLM), which strips out the system's core differentiator entirely.

What follows is an analytical performance estimate built from the system's known mechanics — entry thresholds, position sizing, stop/take-profit geometry, and the signal quality distortions identified above. These are directional ranges, not point estimates.

The system would have been profitable. It has genuine edge from its high-consensus signal threshold and from bracket order discipline. The shortfall versus the benchmark is almost entirely attributable to four mechanics: the fixed 5% take-profit cap on winners, the dead trailing stop, the 2% stop-loss being too tight for high-volatility names, and the fake macro/options signals that dilute the truly informed votes.

03

Gap Registry

C-1 · Crypto has no broker-level stop-loss

Critical
Crypto execution submits plain market orders with stop_price=0.0. There are no bracket child orders. The only protection is a 60-second monitor loop that polls positions and fires a manual close — but only if the monitoring service is running and hasn't lagged. In a crypto flash crash (common: 15–30% drops in minutes), the system has no automatic exit at the broker layer.
Impact: a single BTCUSD or ETHUSD flash crash could wipe 15–30% of any open crypto position before the monitor fires. With crypto allocation up to the max cap, this represents meaningful portfolio risk on every cycle the system holds crypto.
execution/crypto/engine.py · stop_price=0.0 on all market orders

C-2 · MacroEconomist has no macro data

Critical
The MacroEconomist agent receives the same OHLCV bars and computed indicators as the TechnicalAnalyst. It has never seen a yield curve, DXY reading, CPI print, Fed funds rate, or credit spread. Its "macro" opinions are re-interpretations of price action dressed in economic language.
Impact: in macro-driven markets (2022 rate shock, 2025 tariff volatility), this agent produces confident-sounding macro analysis that is entirely fabricated from price data. It takes up 1 of 15 Panel A votes and corrupts the panel's claimed domain diversity. The system is most vulnerable exactly when macro matters most.
brain/agents/macro.py · context = OHLCV indicators only; no FRED / DXY / yield integration

C-3 · Options Flow Analyst has no options data

Critical
The OptionsFlowAnalyst votes based on ATR and Bollinger Band width — two indicators already in every other agent's context. There is no put/call ratio, open interest, implied volatility surface, gamma exposure, or dark pool flow anywhere in the codebase.
Impact: the agent produces invented "options flow" signals that correlate with volatility — useful, but misrepresented. It duplicates the TechnicalAnalyst's volatility view and inflates that dimension's apparent vote weight. The 1 vote it contributes is a phantom signal labeled with false authority.
brain/agents/options_flow.py · context = ATR, Bollinger only; data/market_data.py has no options fetcher

H-1 · Trailing stop is entirely dead code

High
The TrailingStopManager is instantiated, and positions are registered via self._trailing.register() on every BUY. However, update_trailing_stops() is never called from any scheduled loop, any cycle callback, or any background thread anywhere in the codebase.
Impact: every winning trade is capped at the fixed 5% take-profit limit. The system cannot trail a trend — it exits at the first target price regardless of whether the trend is still intact. This single gap is responsible for the largest share of the estimated benchmark shortfall: strong trends (NVDA +200%, META +180% in 2023) are exited at +5% and the position is closed permanently.
execution/stock/engine.py:160 · update_trailing_stops() defined but never scheduled

H-2 · FundamentalAnalyst silently operates on empty data

High
The fundamental data fetch uses yfinance, which fails silently on rate limits, network timeouts, or unrecognized symbols. When it fails, an empty dict is passed to the LLM. The agent proceeds to generate a "fundamental analysis" from no fundamental data.
Impact: the agent's vote is random noise when data is absent, and there is no indicator in the signal output that the fundamental view was data-less. The quality of 1 of 15 Panel A votes is undetectable and frequently worthless. For crypto, the fundamental data is three metrics: BTC dominance, ETH gas, total market cap — regardless of which crypto is being analyzed.
data/market_data.py · yfinance fetch has no retry / fallback / validation

H-3 · Vote thresholds are duplicated and diverge silently

High
watchlist.py exports HOT_MIN_VOTES = 17 and WARM_MIN_VOTES = 11 as the declared single source of truth. However, brain/debate.py does not import these constants — it uses its own hardcoded copies of the same values internally. Changing the thresholds in watchlist.py (e.g. via the Settings page) has no effect on signal generation.
Impact: an operator who adjusts vote thresholds in the settings UI will see the changed values reflected in the config-status API and dashboard, but the debate engine will continue using the old values. This is a silent misconfiguration that will be very difficult to debug in production.
watchlist.py:HOT_MIN_VOTES vs brain/debate.py:threshold=11 (hardcoded)

H-4 · Fixed stop-loss ignores individual asset volatility

High
All stocks and ETFs use a 2% stop-loss regardless of their average true range. TSLA's daily ATR is ~3–5%; a 2% stop is inside normal noise. XLP's daily ATR is ~0.4%; a 2% stop is very wide. The stop-loss geometry is wrong for the majority of the universe and directionally opposite for different asset classes.
Impact: high-volatility names (TSLA, NVDA, SHOP, COIN) get stopped out on normal intraday retracements before the signal's actual invalidation point. Estimated false stop-out rate on these names: 35–45% of otherwise valid setups. Low-volatility names (WMT, JNJ, XLP) carry excessive risk per trade relative to their expected move size.
execution/stock/risk.py · stop_loss_pct default 0.02 applied universally

H-5 · Strategy Coach veto has zero execution effect

High
The Strategy Coach runs in parallel with the Risk Manager and produces ALIGNED / MISALIGNED / CAUTIOUS verdicts. The Risk Manager can veto a trade (set action=HOLD). The Strategy Coach cannot — its MISALIGNED verdict is parsed and stored as strategy_fit in the signal, but there is no code path that changes the execution decision when strategy_fit == "MISALIGNED".
Impact: the Strategy Coach costs an LLM call every cycle but has no effect on whether a trade executes. It adds latency and API cost with no decision benefit. It was designed as a second-opinion check but was never wired into the execution gate.
brain/debate.py:2255 · _parse_strategy_fit() result stored but never gated

M-1 · No position-level correlation management

Medium
The system can simultaneously hold positions in overlapping instruments — XLF (financials ETF) while also holding JPM, BAC, GS, and MS. All five would move together in a rate shock or banking sector event. There is no check for position correlation before entry.
A sector event that hits financials could trigger losses across 5 simultaneous positions, effectively concentrating 25% of portfolio into one factor risk while each individual position appears within the 5% limit.

M-2 · Confidence score is computed but never used in execution

Medium
The signal's confidence field is displayed on signal cards and stored in cache. It is not used to scale position size, widen stops, or gate execution. A HOT BUY with confidence=0.62 gets the same position size as one with confidence=0.95.

M-3 · SMA200 silently degrades to current price when bars insufficient

Medium
When fewer than 200 bars are available (new listings, first run on a symbol), the SMA200 calculation falls back to the current price. This makes the price appear "at the 200-day average" regardless of the actual trend structure, and agents using this indicator produce meaningless trend-relative signals.
brain/debate.py · SMA200 fallback = current close, no explicit warning logged

M-4 · Two circuit breakers with different reset logic

Medium
The stock execution engine has its own circuit breaker that triggers on daily drawdown. The orchestrator has a separate circuit breaker check. They use different threshold sources and have different reset behaviors — one resets on the next equity refresh, the other persists until a manual intervention.
In a multi-loss day, one circuit breaker may have fired while the other has not, creating ambiguous system state that is hard to diagnose from logs.
execution/stock/risk.py:RiskControls vs monitoring/orchestrator.py:circuit_breaker_check

M-5 · Dalio investor persona missing declared context key

Medium
The Dalio investor prompt references regime_label as a context variable. The context dict passed to investor agents does not include this key. The Dalio agent operates on an implicit regime assumption rather than the system's computed regime value.
brain/agents/investors.py:DalioInvestor · regime_label missing from investor context build

M-6 · Sentiment data coverage is thin and unreliable

Medium
The sentiment feed relies on Yahoo Finance RSS (≤20 headlines per symbol) as its primary source. X/Twitter and Alpha Vantage integrations exist in the code but require optional API keys that may not be configured. There is no fallback to alternative sources and no indication in the signal output that sentiment was low-coverage.

M-7 · No per-symbol daily loss limit

Medium
The circuit breaker halts all trading once the portfolio drawdown exceeds the threshold. There is no intermediate guard that stops trading a specific symbol after it has caused two or three consecutive losses — the system will re-enter the same symbol as long as the portfolio-level circuit breaker has not fired.

M-8 · No backtesting infrastructure

Medium
The system has no replay harness, no simulated broker interface, no historical signal persistence layer, and no transaction cost model. Strategy changes cannot be validated against historical data before going live. Every modification is deployed directly into production.
Without backtesting capability, parameter changes (stop-loss %, vote thresholds, position size) must be tuned on live capital, introducing unnecessary risk and slowing the improvement cycle significantly.
04

Improvement Roadmap

The following roadmap addresses every gap above and estimates the incremental return impact of each phase. Phases are sequenced by impact-to-effort ratio — Phase 1 fixes existing code and costs nothing in API spend; Phase 2 adds data; Phase 3 adds intelligence.

Phase 1 · Fix existing code

Activate the infrastructure that already exists

Several high-impact features were built but never connected. Activating them requires no new data sources or API spend — only wiring.
  • Wire the trailing stop loop — call update_trailing_stops() from the orchestrator's per-cycle callback. Allows the system to ride trends rather than exiting at a fixed 5% ceiling.
  • Replace fixed stop-loss with ATR-based sizing — the ATR data is already computed. Use 1.5–2.0× ATR as the stop distance per symbol instead of a flat 2%. This alone eliminates the majority of false stop-outs on volatile names.
  • Import vote thresholds from watchlist.py into debate.py — one import line ensures Settings page changes take effect in signal generation.
  • Wire Strategy Coach veto — add an execution gate: if strategy_fit == "MISALIGNED" and tier is WARM (not HOT), block the trade. This adds a second-opinion check that the coach was designed to provide.
  • Add crypto stop-loss bracket orders — submit OTO sell orders at the broker layer alongside crypto buys, same as stocks. Eliminates C-1 entirely.
  • Scale position size by confidence — full max_position_pct at confidence ≥ 0.85; scale down linearly to 60% at confidence = 0.60. Lets the system size into high-conviction signals more aggressively.
Estimated incremental return from Phase 1 alone: +12–20 percentage points over 3 years — primarily from trailing stop activation allowing trend compounding and ATR-based stops eliminating false exits.
Phase 2 · Real data for fake agents

Give specialist agents the data their expertise requires

The three "fictional" agents (Macro, Options Flow, Sector Rotation) currently add noise. Converting them to genuine specialists using real data is the highest-leverage improvement to signal quality.
  • MacroEconomist — wire FRED API (free, no rate limit) for: Fed funds rate, 2Y/10Y yield spread, CPI YoY, DXY. Add to the agent context. The macro agent's vote will then reflect actual macro conditions for the first time.
  • OptionsFlowAnalyst — wire put/call ratio — CBOE publishes daily equity put/call ratios freely. For individual symbols, add implied volatility rank from Yahoo Finance's options chain (available via yfinance). Replace ATR proxy with real options sentiment data.
  • SectorRotationAnalyst — add cross-sector ETF momentum — fetch the 11 sector SPDR ETFs (XLF, XLE, XLK, etc.) at the start of each cycle and compute relative momentum. Pass cross-sector ranking to the sector rotation agent. Currently impossible because the agent only sees one symbol at a time.
  • FundamentalAnalyst — add retry logic and data validation — 3-attempt retry with exponential backoff for yfinance fetches; mark context as "data unavailable" explicitly when fetch fails rather than passing an empty dict; reduce the agent's vote weight to 0.5× when data is absent.
  • SentimentAnalyst — add a second source — integrate Finnhub's free news API (1000 requests/day) or Stocktwits public feed as a fallback when Yahoo RSS returns fewer than 5 headlines. This doubles sentiment coverage for most symbols at zero cost.
Estimated incremental return from Phase 2: +8–15 percentage points over 3 years — primarily from the macro agent correctly signaling defensive positioning during 2022-style rate shock environments and the 2025 macro-driven volatility.
Phase 3 · Portfolio-level intelligence

Manage the portfolio as a system, not a collection of independent signals

Individual signal quality is one dimension of return. The other is how positions interact. The system currently has no awareness of the portfolio it is building.
  • Correlation-aware position sizing — before entry, compute the correlation of the new signal's symbol to existing open positions (using the past 20 days of returns). If correlation > 0.7, reduce the new position size to 50% of max. Prevents silent concentration in a single factor.
  • Regime-adaptive parameters — in TRENDING markets: widen stop to 2.5× ATR, raise TP to 8%, reduce HOT threshold to 15 votes. In RANGING markets: tighten stop to 1.0× ATR, lower TP to 3%, raise HOT threshold to 19. The regime detector already provides this label — use it to adapt execution geometry.
  • Per-symbol cooldown on consecutive losses — after 2 consecutive losses on the same symbol in a rolling 5-day window, skip that symbol for 2 cycles regardless of signal tier. Addresses M-7 and reduces portfolio drag from repeatedly re-entering broken setups.
  • Dynamic crypto allocation cap — reduce the crypto allocation cap from its fixed percentage to 0 when the macro regime is HIGH_VOLATILITY or TRENDING_DOWN (which real macro data from Phase 2 will accurately detect). Crypto underperforms dramatically in risk-off environments.
  • Backtesting harness (paper-mode replay) — build a historical replay pipeline that feeds past OHLCV data into the paper-mode signal path (rule-based risk manager, deterministic). This will not capture LLM variance but will validate position sizing, stop-loss geometry, and tier thresholds against historical data before any parameter change goes live.
Estimated incremental return from Phase 3: +6–10 percentage points over 3 years, primarily from correlation management preventing sector concentration and regime-adaptive parameters improving the stop/TP geometry in trending vs. ranging conditions.
